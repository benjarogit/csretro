# Security policy

Report security issues privately. Do not open a public issue for a vulnerability
and do not include exploit steps, payloads, or working proof-of-concept attack
code in any report.

Use GitHub private vulnerability reporting on this repository when it is enabled.
If that channel is unavailable, contact the maintainer through a private channel
you already use with them.

## What belongs in a report

- What is affected (client, server module, docs tooling, CI).
- How to recognise the issue without a full exploit walkthrough.
- Impact you expect (crash, data leak, privilege mistake).

## What never belongs in the repository

- Tokens, keys, DSNs, webhook URLs, or `.env` files with secrets.
- Installing CSRETRO into the Steam game directory.
- Connecting a modified CSRETRO client to a VAC-secured server.

This file is the only security policy text. The documentation site and the
GitHub Security Policy link here; they do not keep a second copy.
