# Original CS client bridge

This Linux bridge is the initial port's game-library entry. It exports the existing `F` callback-table ABI using `goldsrc::cldll_func_t`; do not declare a parallel stock ABI. The shipping entry accepts only the registered Default Public i386 game library beside it as `client.valve.so`. The fingerprint registry and SHA-256 implementation are shared with NitroApi. Never open `hw.so` to recognize this game module, and never add fixture fingerprints to the product registry.

The original library owns the game implementations, including movement, prediction, input, HUD and shutdown. Initialization and shutdown wrappers forward to it and own the VGUI binding lifetime. All other table entries remain unchanged. Keep its module alive until the engine has stopped calling that table. Missing required callbacks fail atomically; optional entries remain unchanged. Do not add no-op gameplay exports, replace original movement or call initialization while obtaining the table. The `F` boundary must not propagate C++ exceptions.

After successful original initialization, the bridge verifies the matching `vgui2.valve.so`, creates the single product Surface and binds original VGUI globals and viewport through named symbols. Use the shared ELF symbol resolver, never a parallel parser, hardcoded offsets or casts to the vendored VGUI interfaces. The original client must unload while its VGUI/Surface code is still live. Panel traversal, rendering/input/file callbacks, GameUI/NextClient setup and real Xash runtime assembly remain open; initialization fixtures do not establish a runnable port. No constructor may start a game or load the original library. Native fixtures are our own synthetic test code and do not establish real CS behavior. `tests/xash_client/run.py` builds the same bridge and tests without game files, SDK or vcpkg; product builds use the client presets. Automation never loads the original game library.
